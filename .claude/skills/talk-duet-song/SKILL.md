# 二人（つむぎ × ずんだもん）の曲づくり

このリポジトリで一番うまくいった方向。ユーザーの言葉では「二人がしゃべっているような雰囲気がとても良い」
「少し外れて少し音痴な感じは聞くほど癖になる。歌がそれほどうまくないキャラが頑張って歌っているみたいで、とてもかわいらしい」
「とにかく二人のやり取りを聞き続けていたい」。この空気感を守ることが最優先。

## 基準: 「あめ あめ あめ。」v5
ユーザーの評価: 「非常に完成度が高い。何回も聞きたくなる、単純だがかわいらしさ、中毒性、独自性がある。
ほかのセッションでも同じような雰囲気を再現できるようにしたい」。**新しい曲はこの音から始める。**
- 曲: `songs/ame-ame-ame/score.mjs`、経緯と測定: `specs/song-ame-ame-ame.md`
- 試聴: ページの「あめ あめ あめ。（v5・読み上げ方式・外れ方そのまま）」（id `ame-ame-ame-v5-talk-none`）
- 設定はすべて `src/song/presets.mjs` にある（v5 の音とハッシュ一致で確認済み）:
  ```js
  import { yuruDuetMeta, DUET_SECTION } from '../../src/song/presets.mjs';
  export const meta = yuruDuetMeta({ title: '新しい曲', version: 1, bpm: 128, key: 'A major' });
  const base = DUET_SECTION; // { comp: 'vibes', bass: 'bounce', bassSynth: 'round', pad, guide, duet, phrases }
  ```
  `meta.mix = floatingMix(bpm)` はテンポに合わせてトレモロ（1 拍に 1 回のゆれ）を同期させる。

v5 の要素（どれも外さない）:
1. 二人の掛け合い。ずんだもんが高い声部（A4–D♯5）で淡々としたフック、つむぎが低い声部（C♯4–A4）で受ける。サビは同じ語 ×3 ＋ 句点の間。
2. 読み上げ方式の声（`--mode talk`）。音程補正しない。8 分中心、0.3 秒以内の音。
3. ふわふわした言葉、場面が浮かぶ物語（v5 は飴が降るピンクの空、虫歯というかわいい毒）、擬音は場面の絵に合うもの。
4. 明るいメジャー、128 BPM、王道進行系＋ 7th/9th の甘い和音。
5. 音響: ビブラフォンのトレモロ、パッドとコーラス、深く柔らかい残響（声はプリディレイ）、控えめな打楽器、丸い高域、オルゴールのガイド。
6. 演出なし（セリフ・台本・失敗の場面は入れない）。

## 書き出しと試聴
```
node bin/song.mjs produce songs/<曲> --mode talk [--heta none|weak|mid|strong]
node bin/lab.mjs page          # lab/site/ に試聴ページ（MP3 は ffmpeg）
```
試聴ページは Artifact https://claude.ai/artifact/91zKwk9wYWHvS5j6xYTkGj （同じ URL に再公開する。`file_path: lab/site/index.html`、
新しい MP3 だけ `files` で送る）。ユーザーはページで ★ とメモをつける（db の `ratings`）。比べるときは同条件・同音量で並べる。

**ページは複数のセッションで共有している。** 自分の `lab page` は手元の曲しか知らないので、そのまま公開すると他のセッションの
曲が消える。公開が「newer version」で拒否されたら、作り直さずに、保存された最新版へ自分の項目だけ差し込んでから公開する:
`python3 scripts/merge-page.py <保存された最新版.html> lab/site/index.html lab/site/index.html <自分の clip id> ...`
（`files` には自分の MP3 だけ。テンプレートやほかのグループは最新版のまま残る）

## ユーザーの好み（これまでの判断）
好き:
- 二人の掛け合い（コール＆レスポンス、ハモり、「せーの」でそろう）。ずんだもんの「〜なのだ」。場面が目に浮かぶ言葉。
- 読み上げ方式（`--mode talk`）の声。音から音へ滑らかに移る・少し外れる・語尾が消える・短く弾む＝「頑張って歌う」かわいさ。
- ふわふわした柔らかい言葉、明るいメロディ（A メジャー 128 BPM）、柔らかく残響が多い「ほわんほわん」した音響、中毒的なゆらぎ。
- 伴奏は柔らかく: ビブラフォン（テンポに合わせたトレモロ）、パッドとコーラス、深いリバーブ、丸いベース、控えめな打楽器、オルゴール。
- フックは同じ語の繰り返し＋間（「あめ あめ あめ。」）。

没にしたもの（繰り返さない）:
- 演出: しゃべるセリフ・「挑戦して失敗」などの台本 → 「没入を現実に引き戻す」。歌の外に出ない。
- 読み上げ声への音程補正（`--mode talkhard`/PSOLA）→ ノイズっぽい。外れ方は補正せず「量」を整える（`--heta`）だけ。
- 音節を詰めた早口（「早送り」）、声のスイートスポットより高い旋律、破裂音だらけのフック（輪郭を溶かしたいとき）。
- 言葉: 「ちょうだい」（語呂が悪い）、「ぽとり」（鳥の糞みたい）、「ふわり」（雨の音に合わない）。擬音は場面の絵と合うものを。
- 生成ノイズの伴奏（音楽の形がない）、EDM 的な音（この二人には合わない）。

## 技術的な制約（測定済み）
- 読み上げ声の使える音域: つむぎ C♯4–A4、ずんだもん A4–D♯5（はう F4–D♯5、ニア C♯4–C♯5）。→ つむぎが下、ずんだもんが上。
- 読み上げ声は 0.25 秒を超えて伸ばすと息っぽく消える → `capForTalk` が 0.3 秒で切る。旋律は 8 分中心で書く（128 BPM の 8 分 = 0.23 秒）。
- 無声化の罠: 語頭や子音にはさまれた「む」「う」「ひ」「つ」、16 分の短い音、1 音だけのフレーズは弱くなる → 8 分に延ばす／言葉を替える。
- 助詞「は」は歌唱用に「わ」と書く。「ん」は小さい（検査は音量を見ない）。モーラ数と音符数は一致させる（不一致はエラー）。
- 自動検査 `talkQa` に落ちたフレーズだけ歌唱用の声に差し替わる。ログの「talk fallbacks」が 0 件になるまで楽譜側を直す。
- 「音痴」とは: 読み上げ声は音から音へ滑らかに移り、各音の中心が楽譜から少しずれて着地する（そのままで中央値 35 セント、
  半音以上ずれる音 12%）。語尾は下がって消えやすい（例: 「ぱらり」の「り」が 257 セント低い）。これが「頑張って歌う」かわいさの正体。
- `--heta`（音痴の量）: 1 回歌わせて音ごとのずれを測り、拡大縮小＋キャラの癖（つむぎ 少し低く遅れる / ずんだもん 高音で上ずり走る）で歌い直す。
  計測例: そのまま 中央値 35c・半音以上 12%、中 28c・2%（つむぎの中央値 24c→6c、ずんだもんは 18c→19c でほぼ変わらない）。
  注意: エンジンの応答はキャラで違う（つむぎ 小さな調整は 0.98 倍・大きな調整は 1.58 倍で行きすぎ、ずんだもん 0.5 倍）。
  そのため mid でも「ぱらり」の「り」が -257c → +221c と逆側に行きすぎ、ずんだもんの「高音で上ずる」癖は半分ほどしか効かない。
  `songs/<曲>/out/work/heta-report-<level>.json` に音ごとの前後の値と曲中の時刻が出る。
  既定は「そのまま」（none）。ユーザーは none / mid のどちらとも決めていない。

## 耳に残る設計（「あめ あめ あめ。」v6 で導入）
`node bin/song.mjs analyze songs/<曲> [--hook かな]` で、フックの回数、音域、跳躍、言葉の速さ、フレーズごとの
**アクセントと旋律の一致**（VOICEVOX の読みの高低と、旋律の上下が同じ向きか。○/×で表示。偶然は約 33%）を見る。
1. フック先行: 2 小節のフックを先に決める。畳語・擬音（「カニ カニ カニ。」「あめ あめ あめ。」型: 短い語 ×3 ＋「。」の間）。
   1 曲で十数回聞かせる（v6: 歌 12 回＋オルゴール）。候補は 6〜8 個作って並べ、**翌日に口ずさめたもの**を選ぶ。
2. リズムの型を固定して言葉だけ入れ替える。旋律は山型の単純な形、驚きは 1 か所。
3. A メロ・ブリッジ（おしゃべりの部分）は旋律をアクセントに沿わせる → 二人が「しゃべっている」感じが強まる
   （v6: A メロ 80%、ブリッジ 89%）。サビ（歌の部分）はフックの個性を優先して触らない（v6 のサビは 19% のまま）。
4. 楽器のこだま返し: フックの直後の隙間にオルゴールが同じ音型を返す（演出ではなく音楽の中の掛け合い）。
5. ループする終わり方: 最後をドミナント（A メジャーなら E）とオルゴールのフックで閉じ、イントロへ戻れるようにする。
アクセントを直したら、無声化しやすい語頭（「は」「ひ」など）が検査に落ちることがある → 最初の音を少し上げる（v6「はんぶんこ」）。

## 新しい曲を作る
1. `songs/ame-ame-ame/score.mjs` をコピーして `songs/<新曲>/score.mjs` に。`meta`（title, version, bpm, key, singers, mix）と `sections` を書き換える。
2. 譜面はフレーズ単位: `[開始位置(16分), 'かな:音名:長さ …']`、休符 `-n`、メリスマ `~:音名:長さ`。歌手ごとに `vocal: { a: [...], z: [...] }`。
   セクションの主なフラグ: `chords`, `drums`（yuruVerse / yuruChorus / yuruBreak / none）, `comp: 'vibes'|'marimba'`, `bass: 'bounce'` + `bassSynth: 'round'`,
   `pad`, `bells: 'arp'`, `bellPhrases`（オルゴールの旋律）, `riff` + `riffSynth: 'chip'`, `toys`, `whistle`, `guide`（歌メロを小さくなぞる）, `level: [始, 終]`。
3. `specs/song-<新曲>.md` に狙い・歌詞・判断を書く（CLAUDE.md の手順）。テスト（音域、構造）を `test/song/` に足す。
4. 書き出し → ページ → ユーザーの感想 → 直す。版は残して並べる（`meta.version` を上げる）。

## 広げ方のアイデア（未検証）
- 掛け合いの型を増やす: 輪唱（カノン）、こだま返し、同じ旋律を 3 度でハモる、交互に 1 語ずつ、最後だけユニゾン。
- 場面: 季節や日常の小さな出来事（おやつ、寝る前、お散歩、雨宿り）。言葉は柔らかく、擬音は場面に合わせて。
- テンポと空気: 子守唄（80–90 BPM、オルゴールとパッド）、跳ねる行進（132–140 BPM、トイピアノ）。
- 音色: トイピアノ、カリンバ、チェレスタ、ハープ、ウクレレ風プラック、雨音などの環境音、テープの揺れ（wow/flutter）。
- 声: セクションごとに `--heta` の量を変える、二人の癖をもっと性格づける。ほかの読み上げ声（はう、ニア）とのコンビも測定済みの音域で試せる。
