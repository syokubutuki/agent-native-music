# 二人（つむぎ × ずんだもん）の曲づくり

このリポジトリで一番うまくいった方向。ユーザーの言葉では「二人がしゃべっているような雰囲気がとても良い」
「少し外れて少し音痴な感じは聞くほど癖になる。歌がそれほどうまくないキャラが頑張って歌っているみたいで、とてもかわいらしい」
「とにかく二人のやり取りを聞き続けていたい」。この空気感を守ることが最優先。

代表曲: `songs/ame-ame-ame/`（「あめ あめ あめ。」v5）。経緯と測定はすべて `specs/song-ame-ame-ame.md`。
新しい曲: `songs/yuge-yuge-yuge/`（「ゆげ ゆげ ゆげ。」お風呂の歌、音が加わっていく構成。`specs/song-yuge-yuge-yuge.md`）。

## まず環境（新しいセッションで）
```
scripts/voicevox-install.sh   # 公式 Docker イメージを mirror.gcr.io から取得・検証・展開（約 45 秒、2.1 GB、既にあれば何もしない）
scripts/voicevox-up.sh        # エンジン起動（起動済みなら何もしない）。途中で落ちることがあるので書き出し前に毎回

```

## 書き出しと試聴
```
node bin/song.mjs produce songs/<曲> --mode talk [--heta none|weak|mid|strong]
node bin/lab.mjs page          # lab/site/ に試聴ページ（MP3 は ffmpeg）
```
試聴ページは Artifact https://claude.ai/artifact/91zKwk9wYWHvS5j6xYTkGj （同じ URL に再公開する。`file_path: lab/site/index.html`、
新しい MP3 だけ `files` で送る）。ユーザーはページで ★ とメモをつける（db の `ratings`）。比べるときは同条件・同音量で並べる。

## ユーザーの好み（これまでの判断）
好き:
- 二人の掛け合い（コール＆レスポンス、ハモり、「せーの」でそろう）。ずんだもんの「〜なのだ」。場面が目に浮かぶ言葉。
- 読み上げ方式（`--mode talk`）の声。音から音へ滑らかに移る・少し外れる・語尾が消える・短く弾む＝「頑張って歌う」かわいさ。
- ふわふわした柔らかい言葉、明るいメロディ（A メジャー 128 BPM）、柔らかく残響が多い「ほわんほわん」した音響、中毒的なゆらぎ。
- 伴奏は柔らかく: ビブラフォン（テンポに合わせたトレモロ）、パッドとコーラス、深いリバーブ、丸いベース、控えめな打楽器、オルゴール。
- フックは同じ語の繰り返し＋間（「あめ あめ あめ。」）。

没にしたもの（繰り返さない）:
- 演出: しゃべるセリフ・「挑戦して失敗」などの台本 → 「没入を現実に引き戻す」。歌の外に出ない。
- 読み上げ声への音程補正（`--mode talkhard`/PSOLA）→ ノイズっぽい。外れ方は補正せず「量」を整える（`--heta`）だけ。
- 音節を詰めた早口（「早送り」）、声のスイートスポットより高い旋律、破裂音だらけのフック（輪郭を溶かしたいとき）。
- 言葉: 「ちょうだい」（語呂が悪い）、「ぽとり」（鳥の糞みたい）、「ふわり」（雨の音に合わない）。擬音は場面の絵と合うものを。
- 生成ノイズの伴奏（音楽の形がない）、EDM 的な音（この二人には合わない）。

探索「ふたりの音」の評価（2026-10-22、`specs/song-yuge-yuge-yuge.md` に全文）:
- ★5: 「ゆめごこち」の深い残響（お風呂で歌っている感じ）、1 語ずつ交互（仲の良さ。入りやここぞに）、ウクレレのストローク（踊れる）、つむぎ × ずんだもん。
- ★4: こだま・3 度（さわりの強調に）、最後のユニゾン（響きが美しければ）、トイピアノ（はじける）、はう。
- ★1: 残響の少ない「さっぱり」（声の主張が強すぎる）、輪唱、ハープ（音が合わない）、雨音の環境音。音痴の量は 4 段階とも ★3（好みの差なし）。
- 「音が自然に加わって音楽を形作っていく」発展の形が好き（→「ゆげ ゆげ ゆげ。」）。

## 技術的な制約（測定済み）
- 読み上げ声の使える音域: つむぎ C♯4–A4、ずんだもん A4–D♯5（はう F4–D♯5、ニア C♯4–C♯5）。→ つむぎが下、ずんだもんが上。
- 読み上げ声は 0.25 秒を超えて伸ばすと息っぽく消える → `capForTalk` が 0.3 秒で切る。旋律は 8 分中心で書く（128 BPM の 8 分 = 0.23 秒）。
- 無声化の罠: 語頭や子音にはさまれた「む」「う」「ひ」「つ」、16 分の短い音、1 音だけのフレーズは弱くなる → 8 分に延ばす／言葉を替える。
- 無声子音＋「い/う」（し・ふ・く・す・つ・ち・ひ）は検査に通っても 9–13 dB 沈む（「消えかけ」と言われた）。語頭の短い「い」「う」も弱い。
  `produce` のログ「talk notes under their phrase by 9 dB」で確認できる。ずんだもんの言葉では特に避ける。
- 「ちゃ」が続くとエンジンが「チ/ヤ」と読む → カタカナ「チャプ」で書く。
- 助詞「は」は歌唱用に「わ」と書く。「ん」は小さい（検査は音量を見ない）。モーラ数と音符数は一致させる（不一致はエラー）。
- 自動検査 `talkQa` に落ちたフレーズだけ歌唱用の声に差し替わる。ログの「talk fallbacks」が 0 件になるまで楽譜側を直す。
- `--heta`（音痴の量）: 1 回歌わせて音ごとのずれを測り、拡大縮小＋キャラの癖（つむぎ 少し低く遅れる / ずんだもん 高音で上ずり走る）で歌い直す。
  計測例（533 音）: そのまま 中央値 35c・半音以上 12%、中 28c・2%。ユーザーはまだ最終的な度合いを決めていない。

## 新しい曲を作る
1. `songs/ame-ame-ame/score.mjs` をコピーして `songs/<新曲>/score.mjs` に。`meta`（title, version, bpm, key, singers, mix）と `sections` を書き換える。
2. 譜面はフレーズ単位: `[開始位置(16分), 'かな:音名:長さ …']`、休符 `-n`、メリスマ `~:音名:長さ`。歌手ごとに `vocal: { a: [...], z: [...] }`。
   セクションの主なフラグ: `chords`, `drums`（yuruVerse / yuruChorus / yuruBreak / none）, `comp: 'vibes'|'marimba'`, `bass: 'bounce'` + `bassSynth: 'round'`,
   `pad`, `bells: 'arp'`, `bellPhrases`（オルゴールの旋律）, `riff` + `riffSynth: 'chip'`, `toys`, `whistle`, `guide`（歌メロを小さくなぞる）, `level: [始, 終]`。
3. `specs/song-<新曲>.md` に狙い・歌詞・判断を書く（CLAUDE.md の手順）。テスト（音域、構造）を `test/song/` に足す。
4. 書き出し → ページ → ユーザーの感想 → 直す。版は残して並べる（`meta.version` を上げる）。

## 試作の探索（`songs/explore-duo/`、記録は `specs/explore-duo.md`）
短い試作（20 小節）を方向ごとに並べて聴き比べる仕組み: `node bin/song.mjs explore songs/explore-duo [--only id,…]`。
掛け合いの型（輪唱・こだま・3 度・1 語ずつ・最後だけユニゾン）、音色（トイピアノ・カリンバ・チェレスタ・ハープ・ウクレレ・雨音・テープ揺れ）、
ほわんほわん 4 段階、セクション/キャラごとの音痴、ニア・はうとの組み合わせ。ユーザーの ★ を見て伸ばす方向を決める。
公開は `node bin/lab.mjs page --previous <公開済み index.html>`（手元に無い過去の音源・別セッションの曲を消さない）。
語頭の短い「い」「う」（いいのだ、うたおう）は読み上げ声で検査に落ちやすい。

## 広げ方のアイデア（未検証）
- 掛け合いの型を増やす: 輪唱（カノン）、こだま返し、同じ旋律を 3 度でハモる、交互に 1 語ずつ、最後だけユニゾン。
- 場面: 季節や日常の小さな出来事（おやつ、寝る前、お散歩、雨宿り）。言葉は柔らかく、擬音は場面に合わせて。
- テンポと空気: 子守唄（80–90 BPM、オルゴールとパッド）、跳ねる行進（132–140 BPM、トイピアノ）。
- 音色: トイピアノ、カリンバ、チェレスタ、ハープ、ウクレレ風プラック、雨音などの環境音、テープの揺れ（wow/flutter）。
- 声: セクションごとに `--heta` の量を変える、二人の癖をもっと性格づける。ほかの読み上げ声（はう、ニア）とのコンビも測定済みの音域で試せる。
